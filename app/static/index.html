Payments That Don't Stop When Connectivity Does.

DRUNIX Pay enables resilient small-value digital payments across unreliable connectivity environments (rural outposts, underground metro basements, network congestion), with tamper-evident local vault handling, instant duplicate protection, and automated multi-way reconciliation.

The Core Architecture Paradigm
PAY NOW → SECURELY STORE → VERIFY → SYNC → RECONCILE
“Offline is not the feature. Resilience is the feature.”

Traditional payment systems fail completely when connectivity drops, leading to uncertain transaction states, repeated payment attempts, customer anxiety, and merchant refusal. DRUNIX Pay solves this through eight foundational pillars:

1. Connectivity Failure
Zero app crashes; seamless fallback to local secure storage.
2. Transaction Uncertainty
Clear, honest status: 'Payment securely recorded — waiting for sync'.
3. Duplicate Payment Risk
Intelligent heuristics flag duplicate taps to prevent double billing.
4. Local Secure Vault
Hardware keystore attestation and HMAC-SHA256 tamper-evidence.

⚡ Duplicate Payment Protection Innovation Core Hackathon Feature

In areas with unstable connectivity, customers frequently tap 'Pay' repeatedly fearing the first attempt was dropped. DRUNIX Pay deploys a multi-variable contextual filter to intercept identical payments before double-debiting.

⚠ Simulated Duplicate Detection Scenario

User completed an offline payment of ₹450 to Sharma General Store. User immediately presses Pay again.

INTERCEPTION HEURISTICS:
  • Exact Merchant ID match within 180s sliding window
  • Identical transaction amount (₹450)
  • Same physical device hardware fingerprint
  • Existing local record in 'WAITING_FOR_SYNC' state
